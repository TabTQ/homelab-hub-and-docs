    Editing (WYSIWYG, same layout as reading).
    • Type as usual. Markdown shortcuts work (## , - , ```, > ). Type / for the block menu. Paste or drag an image anywhere to upload it.
    • Blocks have a drag handle (⋮⋮) on hover. When the cursor is in a table, a small toolbar appears (add/remove row or column, header row, merge).
    • A Mermaid block is a code box with a live preview next to it. On save, the editor turns it into an SVG (light and dark), so the public site never loads Mermaid.
    • Autosave keeps a local draft every few seconds. Save stores a draft version on the server (Ctrl+S). It never changes the public page. Publish… does.

      Page settings and Publish (one dialog).
      • A page is public only when Public is on and it has a hostname. Type the sub-domain and pick the domain (from DOCS_DOMAINS). The check runs as you type: valid label, allowed domain, not used by another page.
      • The pre-publish checks list what the visitor will get: links to internal pages become plain text, links to other public pages go to their hostname, and files that will be copied to the public side are listed.
      • Publish copies the current draft to the public side (live within seconds). Unpublish takes the hostname offline at once (visitors get 404) but keeps the hostname reserved for this page. Changing the hostname kills the old link.
      • Parent and position can also be changed here (the tree's drag and drop does the same).

      Webapp page: settings, bundles and live preview.
      • Upload a single index.html or a .zip (it must contain index.html at the top or in one top folder). Each upload becomes a new bundle (b1, b2, …). The newest is the draft. Publish makes it live. Use on an older bundle rolls back.
      • Display: Full page (the app fills the browser, no hub header) or Framed (page title, text above and below, app in a frame). Height: fixed px, auto (the app reports its height) or viewport.
      • Network: by default the app can load only files from its own bundle. Tick a CDN to allow it. The app always runs in a sandbox: it cannot see the hub, its cookies or its APIs.
      • The theme (light/dark) is passed to the app. The preview on the right is a real sandboxed iframe: click the nodes and try the theme buttons.

      What a visitor sees.
      • Exactly one page per hostname. No tree, no breadcrumbs, no search, no list of other pages. A small header with the page title and a theme button, and a footer with the "last updated" date. No hub branding unless you want it.
      • Links to other public pages are normal links to their hostname. Links to internal pages are plain text.
      • A webapp page in full page mode is just the app filling the window. An unknown hostname gets a plain 404 that says nothing about which pages exist.
      • Every response: X-Robots-Tag: noindex, nofollow, robots.txt disallows all, strict CSP, no third-party requests (except CDNs you allowed for one app, inside its sandbox).
